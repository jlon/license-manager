# 社区版 Web UI 整体升级需求

**状态：已确认（20260819）**

## 一、背景与目标

雪松软件授权系统企业版的 Web UI 已经过持续优化并趋于稳定，社区版仍存在首页信息层级不清、页面视觉不统一、部分布局在常用分辨率下不稳定、操作反馈不完整等问题。

本次工作对社区版现有 Web UI 进行分阶段整体升级。升级只改善现有功能的呈现、操作效率、一致性和兼容性，不新增社区版业务能力，也不将企业版专属模块或数据口径迁入社区版。

目标如下：

1. 建立统一、清晰、稳定的社区版管理端视觉和交互基线。
2. 升级首页看板，使现有数据更易读、更有业务层次。
3. 统一核心管理页面的查询、列表、表单、详情和状态反馈。
4. 改善常用桌面分辨率及手机、平板浏览器下的可用性。
5. 在不改变现有业务能力和接口响应的前提下降低后续维护成本。

## 二、功能范围

### 2.1 本次范围

#### 公共框架

- 登录页。
- 顶部导航、侧边导航、页面内容容器和面包屑呈现。
- 页面标题、按钮、卡片、表格、表单、状态标签、分页、弹窗和反馈状态的统一。
- 中文、英文、日文界面的一致性。
- 常用桌面分辨率以及手机、平板浏览器兼容。

#### 首页看板

- 现有统计指标的重新分组和视觉升级。
- 现有授权趋势的展示和时间范围交互优化。
- 现有近期授权列表的密度、状态和时间展示优化。
- 首页加载、空数据、失败和重试反馈。
- 首页与现有管理页面之间的合理导航，不增加新的业务动作。

#### 现有管理页面

- 客户管理：列表、创建、编辑和详情。
- 授权管理：客户选择入口、授权列表、创建和详情。
- 发票管理：汇总、列表、详情、审核和文件相关操作。
- 套餐管理：列表、创建、编辑和状态管理。

#### 质量改进

- 修正前端展示类型与实际数据不一致的问题。
- 清理用户不可见的调试输出和失效样式。
- 优化大图片、字体及页面资源加载体验。
- 保证危险操作确认、成功提示、失败提示和重试行为一致。

### 2.2 不在本次范围

- 不新增社区版菜单、模块、角色或权限能力。
- 不启用当前未在侧边导航开放的角色管理和用户管理入口。
- 不迁入企业版的产品项、功能模板、设备台账、审计日志、API Key、菜单管理和系统配置。
- 不迁入企业版的试用授权、激活后计时、产品维度授权、激活来源和企业版权限控制。
- 不新增销售、订单、支付、用户自助端或移动应用功能。
- 不改变现有数据库结构、授权协议、激活流程和许可证文件格式。
- 不直接采用企业版首页的专属统计口径或专属接口。
- 不以本次 UI 升级为由重构与页面体验无关的后端业务代码。

## 三、分阶段实施范围

### 阶段一：首页看板与公共框架

- 统一页面容器、基础间距、标题层级、卡片和状态颜色。
- 优化顶部导航和侧边导航的稳定性及选中反馈。
- 重构首页信息层级和响应式布局。
- 保留并重新呈现社区版现有全部首页指标、授权趋势和近期授权。
- 补齐首页加载、空数据、失败和重试状态。

### 阶段二：客户与授权核心流程

- 统一客户列表、客户表单和客户详情的页面结构。
- 梳理授权入口与授权列表之间的操作路径，减少不必要的视觉割裂。
- 统一授权查询、创建、详情、状态和危险操作反馈。
- 保持现有创建、锁定、解锁、删除、下载和设备解绑规则不变。

### 阶段三：发票与套餐

- 将两个现有模块纳入统一的列表、查询、表单、详情和反馈规范。
- 保留各模块当前业务字段、状态和操作权限。
- 优化信息密度及较小桌面宽度下的布局。

### 阶段四：兼容性与质量收口

- 完成手机、平板和常用桌面分辨率回归。
- 完成中、英、日三种语言的溢出和缺失检查。
- 完成键盘操作、焦点、文字对比度和基础可访问性检查。
- 清理调试输出、重复样式和无效资源。
- 完成生产构建和核心操作路径回归。

## 四、功能点与验收标准

### 4.1 公共视觉与布局

- 页面使用一致的背景、内容边距、卡片边界、标题字号和操作区布局。
- 同类主操作、次操作和危险操作在不同页面具有一致的视觉语义。
- 侧边导航展开、折叠和当前页面状态明确，内容区不被遮挡或产生异常空白。
- 1280×720、1366×768、1440×900、1920×1080 下无非业务需要的横向滚动和内容裁切。

### 4.2 首页看板

- 首页展示社区版当前已有的全部统计指标，数值及含义不改变。
- 正常、增长和风险信息具有清晰的视觉层级，风险数值不依赖颜色才能识别。
- 授权趋势在周、月和自定义日期场景下完整显示，坐标轴和提示信息不被裁切。
- 近期授权在常用桌面宽度下无需依赖超宽列才能阅读；窄屏下仍可查看核心字段。
- 任一首页请求失败时，不影响其他已成功区域展示，并提供可理解的失败反馈。
- 首页无数据时展示明确空状态，不出现空白卡片或永久加载状态。

### 4.3 列表与查询

- 同类列表页面的查询区、表格、状态、操作列和分页位置一致。
- 查询、重置、分页和刷新后的条件及结果符合当前业务规则。
- 长文本、授权码、日期和状态在常用分辨率下不相互遮挡。
- 空数据、加载中和加载失败三种状态可以明确区分。

### 4.4 表单与详情

- 表单按业务信息分组，必填项、帮助信息和校验错误清晰。
- 提交过程中防止重复操作，成功和失败均有明确反馈。
- 详情页信息层级统一，返回路径稳定，现有业务操作保持可用。
- 危险操作继续要求确认，且确认文案说明具体影响对象。

### 4.5 响应式与多语言

- 手机和平板浏览器下导航可打开、关闭，页面主体可滚动且不会被遮挡。
- 表格在窄屏下采用可控的横向查看或信息降级，不压缩到不可读。
- 中文、英文、日文切换后无关键按钮缺字、标题重叠或布局断裂。

### 4.6 兼容性与稳定性

- 不改变现有接口响应结构和已有业务操作结果。
- 不增加数据库迁移和部署必填配置。
- 前端生产构建通过。
- 首页、客户、授权、发票和套餐的核心路径完成回归。
- 企业版专属菜单、字段和入口不出现在社区版界面中。

## 五、整体完成标准

- 四个阶段均完成需求确认、详细设计、代码实现和验收。
- 社区版所有当前可见管理端页面使用同一套视觉与交互规范。
- 首页、核心业务页面和公共框架不再依赖针对单一分辨率的临时布局补丁。
- 社区版业务范围、接口兼容性和部署方式保持不变。

## 六、待确认问题

1. 是否确认按“阶段一：首页看板与公共框架”开始详细设计和实施？
2. 授权管理菜单是否继续先进入客户选择页，还是改为直接进入全部授权列表，并保留客户筛选？该调整不新增业务能力，但会改变现有入口流程。
3. 登录页是否在阶段一同步升级，还是放到阶段四统一收口？

## 七、确认结果

- 按阶段一开始详细设计和实施。
- 授权管理默认进入全部授权列表，客户筛选在核心流程阶段继续保留和优化。
- 登录页纳入阶段一同步升级。
