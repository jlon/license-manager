# 社区版仪表盘业务数据升级设计

## 一、方案概述

社区版仪表盘新增“首页聚合数据”和“双业务趋势”两个接口，将页面数据分为：

1. 经营概览。
2. 云端托管推广。
3. 到期提醒。
4. 业务趋势。
5. 最近授权与最近激活。

页面不直接搬运企业版样式，继续使用社区版现有的颜色、边框、卡片、字号、间距、骨架屏和失败重试规范。

## 二、数据模型与口径

### 2.1 有效授权

授权码同时满足以下条件时计入有效授权：

- 未锁定。
- 结束时间不早于当前时间。

有效授权下：

- 存在至少一个状态为 `active` 的许可证，计为已激活授权。
- 不存在状态为 `active` 的许可证，计为未激活授权。

### 2.2 已激活设备

统计未删除且状态为 `active` 的许可证数量。社区版每个许可证对应一次设备激活，因此该数量作为已激活设备数。

### 2.3 剩余激活名额

仅统计有效授权码，每个授权码的剩余名额为：

`max(最大激活数 - 当前 active 许可证数, 0)`

仪表盘展示所有有效授权码剩余名额之和。

### 2.4 到期提醒

排除已锁定授权，按授权码结束时间分为互不重叠的三组：

- 7 天内到期：结束时间大于当前时间，且不晚于当前时间后第 7 天。
- 8–30 天到期：结束时间大于第 7 天，且不晚于第 30 天。
- 已过期：结束时间早于当前时间。

每组返回：

- 授权码数量。
- 该组授权码下状态为 `active` 的许可证数量。

### 2.5 最近数据

最近授权默认返回最新 5 条授权码，包含：

- 授权码 ID。
- 客户名称，无客户时返回空字符串。
- 授权描述。
- 创建时间和到期时间。
- 已激活数、最大激活数和授权状态。

最近激活默认返回最近完成激活的 5 条许可证，包含：

- 许可证 ID 和授权码 ID。
- 客户名称，无客户时返回空字符串。
- 授权描述。
- 硬件指纹。
- 激活时间和授权到期时间。

## 三、接口设计

### 3.1 首页聚合数据

`GET /api/v1/dashboard/home`

响应 `data` 结构：

```json
{
  "generated_at": "2026-09-01T18:00:00+08:00",
  "overview": {
    "valid_authorizations": {
      "total": 0,
      "activated": 0,
      "not_activated": 0
    },
    "activated_devices": {
      "total": 0
    },
    "remaining_activation_slots": 0
  },
  "expiry_reminders": {
    "due_7_days": {
      "authorization_count": 0,
      "affected_device_count": 0
    },
    "due_8_to_30_days": {
      "authorization_count": 0,
      "affected_device_count": 0
    },
    "expired": {
      "authorization_count": 0,
      "affected_device_count": 0
    }
  },
  "recent_authorizations": [],
  "recent_activations": []
}
```

该接口不返回企业版权限矩阵、产品套餐或试用来源数据。

### 3.2 双业务趋势

`GET /api/v1/dashboard/trends`

查询参数：

- `period`：`7d`、`30d` 或 `custom`，默认 `30d`。
- `start_date`：自定义开始日期。
- `end_date`：自定义结束日期。
- `timezone`：浏览器 IANA 时区。

响应 `data` 结构：

```json
{
  "period": {
    "type": "30d",
    "start_date": "2026-08-03",
    "end_date": "2026-09-01"
  },
  "authorization_creation_trend": [
    { "date": "2026-09-01", "count": 0 }
  ],
  "activation_trend": [
    { "date": "2026-09-01", "count": 0 }
  ]
}
```

自定义日期范围必须完整，开始日期不得晚于结束日期，且时间跨度不超过 365 天。

### 3.3 旧接口兼容

以下旧接口保留，本次不删除、不改变响应结构：

- `GET /api/v1/stats/overview`
- `GET /api/v1/dashboard/authorization-trend`
- `GET /api/v1/dashboard/recent-authorizations`

## 四、核心逻辑流程

### 4.1 首页加载

1. 页面进入后并行请求首页聚合数据和双业务趋势。
2. 聚合数据驱动概览、到期提醒和最近记录。
3. 趋势数据独立加载，切换时间范围时不重新加载首页聚合数据。
4. 手动刷新时并行刷新两类数据，并更新页面的最后刷新时间。

### 4.2 错误与空数据

- 首页聚合数据失败时，概览、到期提醒和最近记录展示可重试错误状态。
- 趋势请求失败时，仅趋势区域展示错误和重试入口。
- 统计值为 0 时正常展示 0，不按加载失败处理。
- 最近记录为空时使用现有空状态组件。

## 六、影响范围与风险

### 6.1 现有未提交改动

当前工作区中已有客户 ID 可空、授权码删除校验及相关错误文案改动。本次实现只在相关文件上进行增量合并，不回退、改写或整文件覆盖这些改动。

### 6.2 数据库性能

- 首页聚合使用固定数量的范围查询和预聚合，不按授权码或日期逐条访问数据库。
- 趋势分别查询授权码创建时间和许可证激活时间，再在内存中按日汇总和补齐。

### 6.3 兼容性

- 不删除旧路由和旧响应结构。
- 不改变授权码、许可证和客户的数据库结构。
- 新增响应中的客户名称允许为空，适配当前工作区正在引入的无客户授权码。

## 七、测试计划

1. 后端单元测试：趋势缺失日期补 0、时区转换、自定义区间校验。
2. 后端查询测试：聚合查询、无客户授权、空数据响应。
3. 后端全包编译检查：`go test ./... -run '^$'`。
4. 前端类型检查和生产构建：`pnpm run build:prod`。
5. 页面冒烟：概览、到期提醒、双趋势、最近记录、云端托管区、刷新、空数据和失败重试。
