# 阶段二：客户与授权核心流程详细设计

**日期：20260819**  
**状态：已确认（20260819）**

## 一、方案概述

阶段二按“客户流程 → 授权列表 → 授权表单与详情 → 许可证设备”的顺序实施，在阶段一公共布局和视觉变量上继续收口，不另建一套页面框架。

设计原则：

1. 页面状态保持扁平：每个列表只维护查询条件、分页、加载、错误和结果五类状态。
2. 查询和业务动作分离：查询只负责更新列表，启禁用、锁定、撤销等动作各自维护提交状态。
3. 页面内逻辑优先就地表达；只有复杂且职责独立的详情弹窗拆为页面私有组件。
4. 不复制企业版整页代码，只参考信息层级、操作密度和响应式处理。
5. 删除重复媒体查询、视口比例尺寸和强制超宽补丁，使用阶段一既有变量和少量清晰断点。
6. 不改变后端、数据库、路由业务语义和接口响应结构。

## 二、数据模型变更

### 2.1 数据库与后端

无数据库表、字段、索引、迁移和 Go 模型变更。

### 2.2 前端类型修正

只修正与现有后端响应不一致的 TypeScript 声明：

- 许可证设备状态统一为 `active | inactive | revoked`。
- 许可证设备查询状态与后端现有枚举一致，不再声明后端不支持的 `expired`。
- 可选时间、IP、显示名称和设备信息继续保持可选，不使用空字符串冒充必填值。
- 客户和授权接口的统一响应外形保持不变。

不增加企业版产品、设备台账、功能模板或激活来源字段。

## 三、接口设计

### 3.1 接口变更结论

本阶段不新增、不删除、不修改后端接口。

### 3.2 现有接口复用

| 页面/动作 | 现有接口 |
| --- | --- |
| 客户列表、详情、创建、编辑、删除、状态 | `/api/customers` 现有接口组 |
| 授权列表、详情、创建、编辑、删除 | `/api/v1/authorization-codes` 现有接口组 |
| 授权锁定与解锁 | `/api/v1/authorization-codes/:id/lock` |
| 授权期限变更 | `/api/v1/authorization-codes/:id/renew` |
| 授权文件下载 | `/api/v1/authorization-codes/:id/download` |
| 许可证设备列表、详情和创建 | `/api/v1/licenses` 现有接口组 |
| 许可证文件下载 | `/api/v1/licenses/:id/download` |
| 撤销许可证 | `/api/v1/licenses/:id/revoke` |
| 授权变更记录 | `/api/v1/authorization-codes/:id/changes` |
| 页面枚举 | `/api/v1/enums` 现有接口组 |

### 3.3 错误处理约定

- 增加一个纯前端错误信息解析函数，按“后端业务消息 → 响应消息 →普通错误消息 → 页面默认文案”的顺序返回字符串。
- 列表和详情首次加载失败时，在内容区域显示错误和重试按钮，不自动离开页面。
- 创建、更新、状态切换、下载和撤销失败继续使用消息提示，并保留用户当前输入和页面数据。
- 生产代码删除普通调试输出；不记录令牌、完整响应和授权文件内容。

## 四、页面结构设计

### 4.1 客户列表

页面结构：

```text
页面说明                                      新增客户

查询卡片
客户类型  客户等级  状态  关键字             查询  重置

列表卡片
客户信息 / 联系人 / 等级 / 状态 / 创建时间 / 操作
错误或空状态
分页
```

状态结构：

```ts
filters = { customerType, customerLevel, status, keyword }
pagination = { page, pageSize, total }
listState = { loading, error, rows }
```

流程：

- 进入页面并行加载枚举和客户列表；枚举失败不清空已成功列表。
- 点击查询后页码归 1，再按当前条件请求。
- 点击重置清空全部条件、页码归 1 并重新请求。
- 切换分页只改变分页，不重置已应用条件。
- 启禁用和删除只锁定当前操作，成功后刷新当前页；删除最后一条时回到上一有效页。
- 操作列保留“查看授权、编辑、启禁用、删除”，桌面直接显示，窄屏使用清晰的更多操作菜单。

样式策略：

- 删除固定 `1408px` 表格宽度、视口比例列宽和重复断点覆盖。
- 表格容器负责横向滚动，页面本身不横向滚动。
- 桌面操作列保持可读最小宽度，手机不强行同时铺开四个按钮。

### 4.2 客户表单

表单分为：基本信息、联系信息、企业信息三个现有信息组。

- 页面头部固定呈现返回、标题、取消和保存。
- `detailLoading` 与 `submitting` 分开，避免加载详情时按钮状态和提交状态混用。
- 枚举与详情分别加载；详情失败显示重试，不呈现可误提交的空编辑表单。
- 保存前使用现有表单校验；提交成功回到客户列表并刷新，失败保留输入。
- 本阶段不新增离开页面拦截，只保留现有取消路径，避免引入额外流程复杂度。

### 4.3 客户详情

- 使用统一页面头部和返回入口。
- 按基本信息、联系信息、企业信息、授权概览展示现有字段。
- 授权数量、活跃数量等只展示现有响应数据，不新增统计请求。
- 加载失败留在详情页并提供重试，不自动返回列表。
- 长地址、邮箱和备注允许自然换行；空值统一显示 `-`。

### 4.4 授权列表与客户筛选

页面结构与客户列表保持同一层级，但不强制共用复杂列表组件。

状态结构：

```ts
filters = { customerId, customerName, code, status }
pagination = { page, pageSize, total }
listState = { loading, error, rows }
```

客户筛选流程：

```text
进入授权列表
  → 读取路由中的 customerId/customerName
  → 有客户条件：显示并按客户查询
  → 无客户条件：查询全部授权
用户查询或重置
  → 同步当前客户条件到路由
  → 页码归 1
  → 请求列表
```

- 客户选择支持现有客户数据搜索，不新增后端能力。
- 从客户页面进入时保留客户条件；重置后回到全部授权。
- 查询按钮是唯一的条件应用入口，避免选择过程中连续触发多次列表请求。
- 创建、详情、锁定、解锁和删除保持当前业务规则。
- 每个危险操作维护当前行 ID，避免整表进入加载态。

### 4.5 授权创建表单

- 保留社区版当前全部字段和校验，不迁入企业版产品维度字段。
- 页面按客户与说明、有效期与激活数、授权配置三个区块组织。
- 客户搜索、枚举加载、详情加载和提交状态分别维护。
- JSON/键值配置继续复用现有编辑器，不另造配置组件。
- 提交前集中生成一次请求数据，不在模板和多个监听器中重复转换。
- 创建成功返回授权列表；若从客户上下文进入，保留该客户筛选。

### 4.6 授权详情

父页面只负责：

- 加载授权详情。
- 展示授权码、状态、返回入口和顶部操作。
- 管理四个现有页签。
- 下载授权文件。
- 在子操作成功后刷新详情。

两个复杂操作拆为页面私有组件：

- `ChangeValidityDialog`：只负责期限类型、日期、原因、校验和提交。
- `UpdateAuthorizationDialog`：只负责变更类型、激活数、配置、原因、校验和提交。

两者通过 `modelValue` 控制显示，通过 `success` 通知父页面刷新，不访问路由、不维护详情页其他状态。这样缩短父页面，不建立跨业务通用弹窗框架。

响应式：

- 桌面使用横向页签，替代占用固定宽度的详情内侧栏。
- 窄屏页签可横向滚动，顶部操作自动换行。
- 详情加载失败留在当前页，显示返回和重试。

### 4.7 许可证设备信息

状态结构：

```ts
deviceState = { loading, error, rows }
downloadingIds = Set<string>
revokingIds = Set<string>
addDialog = { visible, submitting }
```

加载流程：

```text
进入许可证页签
  → 请求当前授权下的设备列表
  → 按现有详情接口补充需要的设备信息
  → 单台详情失败：保留列表基础信息
  → 列表请求失败：显示区域错误与重试
```

设备卡片：

- 头部展示设备序号、在线状态、地址和最近活跃时间。
- 内容展示硬件指纹、许可证编号和许可证状态。
- 长值使用等宽文本、可换行和复制按钮，不截断真实值。
- 底部保留下载与撤销；加载状态按设备 ID 隔离。
- 已撤销设备禁用撤销按钮，仍允许查看历史信息。
- 撤销使用现有原因输入确认框，不更名为删除设备，不新增解绑接口。

添加设备弹窗：

- 保留授权码只读展示、硬件指纹和备注。
- 弹窗宽度使用 `min(520px, calc(100vw - 32px))`，手机端按钮可纵向排列。
- 提交成功关闭弹窗并刷新设备列表；失败保留输入。

## 六、核心状态流程

### 6.1 列表请求

```text
触发查询/分页/刷新
  → 清除本次错误
  → 设置 loading
  → 组合已应用条件与分页
  → 请求现有接口
  → 成功：更新 rows、total
  → 失败：保留条件，显示区域错误
  → 结束 loading
```

### 6.2 危险操作

```text
点击启禁用/删除/锁定/解锁/撤销
  → 显示包含对象名称或编号的确认
  → 用户确认
  → 设置当前对象提交状态
  → 调用现有接口
  → 成功：提示并刷新相关区域
  → 失败：提示后端可读消息，保留页面数据
  → 清除当前对象提交状态
```

### 6.3 详情刷新

```text
子弹窗或设备操作成功
  → 关闭对应弹窗
  → 刷新授权详情或设备区域
  → 不重建整个页面，不重置当前页签
```

## 七、影响范围与风险

### 7.1 页面重构风险

风险：清理历史样式时可能影响固定列、弹窗层级和窄屏滚动。

处理：按客户列表、授权列表、详情、设备四个小批次实施，每批完成类型检查和目标分辨率验证后再进入下一批。

### 7.2 路由客户条件

风险：查询重置与浏览器前进后退可能造成界面条件和结果不一致。

处理：只把客户上下文同步到现有路由查询参数；页面进入时读取一次，查询和重置时显式更新，其他筛选保持页面内状态，避免复杂双向监听。

### 7.3 企业版参考污染

风险：对应企业版页面包含产品和设备台账依赖。

处理：逐字段复用社区版现有接口；出现 `product`、`deviceLedger`、`featureTemplate` 等依赖时直接排除，不复制整文件。

### 7.4 公共样式影响

风险：阶段二样式误伤阶段三尚未改造页面。

处理：业务样式保持局部作用域；全局只复用阶段一变量，不新增针对 Element Plus 全局表格或弹窗的覆盖。
