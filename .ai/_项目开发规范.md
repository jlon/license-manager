# 雪松软件授权系统社区版开发规范

## 分层规范

- 前端页面负责展示、交互编排和页面级状态，不直接拼接后端地址或复制请求逻辑。
- 可跨页面复用的布局、状态展示和输入组件放入公共组件目录；仅单页使用的内容保留在页面目录。
- 前端接口类型与后端实际响应保持一致，现有响应结构未经确认不得修改。
- 后端遵循处理器、服务、仓储、模型分层；处理器不承载业务规则，仓储不承载页面展示逻辑。
- 社区版可以参考企业版实现，但必须逐项确认依赖和产品边界，不整文件覆盖或带入企业版专属能力。

## 命名约定

- Vue 组件使用 PascalCase，组合式函数使用 `use` 前缀，普通变量和函数使用 camelCase。
- 页面、组件和样式名称表达业务语义，避免继续新增拼写错误或含糊缩写。
- Go 包名使用小写单词，导出类型和函数使用 PascalCase，非导出成员使用 camelCase。
- 多语言键按模块分组，新增可见文字必须同时维护中文、英文和日文资源。

## 错误处理

- 页面必须区分加载中、空数据、请求失败和正常数据四种状态。
- 用户可恢复的失败提供明确提示和重试入口；危险操作必须二次确认。
- 前端优先展示后端可读错误信息，不向用户显示堆栈或内部实现细节。
- Go 错误向上返回并保留上下文，不静默吞错；可预期业务错误使用项目现有多语言错误体系。

## 接口规范

- 保持现有统一响应结构和字段命名，不因 UI 重构改变业务接口契约。
- 查询条件、分页和排序继续使用现有接口能力；新增筛选前先确认后端已支持。
- TypeScript 接口类型必须与 Go 响应模型一致，时间、标识符和状态值不得用错误类型代替。
- 本次 Web UI 升级默认不新增聚合接口；只有现有接口确实无法满足已确认需求时，才进入单独设计确认。

## 日志规范

- 生产前端不得保留普通调试输出；必要错误日志应简洁且不包含令牌、个人信息或完整敏感响应。
- 后端使用项目统一日志组件，记录请求上下文和可定位信息，不记录密码、密钥、验证码和完整授权文件。
- 临时排查日志在交付前移除，不能依赖日志输出作为用户反馈。
