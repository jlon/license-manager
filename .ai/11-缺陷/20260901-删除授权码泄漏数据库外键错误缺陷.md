# 删除授权码泄漏数据库外键错误缺陷

## 问题描述

- 操作：在管理端删除已经产生许可证的授权码。
- 现象：接口直接向用户返回 MySQL 外键约束错误：

  ```text
  Error 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (`license_manager`.`licenses`, CONSTRAINT `fk_licenses_authorization_code` FOREIGN KEY (`authorization_code_id`) REFERENCES `authorization_codes` (`id`))
  ```

- 环境：Windows 开发环境；后端使用 Go、GORM 和 MySQL。

## 影响范围

- 影响管理端“删除授权码”接口及其前端错误提示。
- 仅在授权码已经存在关联许可证时触发。
- 数据库外键成功阻止了错误删除，现有许可证和授权码数据未被破坏。

## 根因分析

### 直接原因

`backend/internal/repository/authorization_code_repository.go` 的 `DeleteAuthorizationCode` 直接对授权码执行 GORM 删除。当前 `AuthorizationCode` 模型没有 `DeletedAt` 字段，因此这里实际执行物理删除。`licenses.authorization_code_id` 通过 `fk_licenses_authorization_code` 引用授权码主键；关联许可证仍存在时，MySQL 外键阻止删除父记录并返回 1451。

### 用户看到数据库错误的原因

`backend/internal/service/authorization_code_service.go` 的 `DeleteAuthorizationCode` 没有在删除前检查关联许可证。仓储返回的数据库错误随后通过 `i18n.NewI18nError("900004", lang, err.Error())` 作为自定义消息写入统一错误响应，因此 MySQL 库名、表名、约束名和 SQL 错误原文直接暴露给前端。

### 与 SaaS 版的差异

参考项目 `C:\B-work\thingspanel-work\0-m\01-saas\license-manager-saas` 已在相同业务路径增加以下处理：

1. `authorization_code_service.go` 删除前调用 `CheckAuthorizationCodeHasLicenses`。
2. 存在关联许可证时返回授权模块业务错误 `300013`，而不是执行删除。
3. `license_repository.go` 通过授权码 ID 查询未软删除许可证是否存在。
4. 多语言资源提供“授权码存在有效的许可证，无法删除”等用户可读提示。
5. 无关联许可证时，仓储在事务内先清理授权变更记录，再删除授权码，避免另一条关联关系继续阻止删除。

当前社区版的 `authorizationCodeService` 已经注入 `LicenseRepository`，但该接口和实现缺少 `CheckAuthorizationCodeHasLicenses`，多语言资源也没有对应业务错误码。

## 根因结论

这是可预期的业务冲突没有在服务层转译造成的错误体验，不是数据库异常。正确边界是保留外键保护，在删除前识别关联许可证并返回稳定、可本地化的业务错误，不能把原始数据库错误暴露给用户。

## 相关代码

- `backend/internal/service/authorization_code_service.go:472`：删除授权码服务入口。
- `backend/internal/service/authorization_code_service.go:499`：将仓储错误原文作为 `900004` 消息返回。
- `backend/internal/repository/authorization_code_repository.go:181`：直接删除授权码。
- `backend/internal/repository/interfaces.go:88`：当前许可证仓储接口缺少关联许可证检查能力。
- `backend/configs/i18n/errors/`：当前缺少删除冲突对应的中、英、日错误文案。

## 待确认问题

- 建议沿用 SaaS 版业务规则：只要授权码仍有关联许可证，就禁止删除并提示用户先处理许可证；不级联删除有效许可证。
- 对已无关联许可证的授权码，建议在一个事务内先删除其授权变更历史，再软删除授权码，避免后续被 `authorization_changes` 外键拦截。
